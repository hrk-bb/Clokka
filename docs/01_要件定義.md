## 1. 目的と背景

Clokka は、社員がスマートフォンから日々の出退勤を登録し、月末の勤務実績の**提出忘れをなくす**ためのブラウザWebアプリである。管理者は月ごとの提出状況を一覧・並べ替え・確認し、確定データをExcel形式で出力できる。

主な成功指標は次のとおりとする。

| 指標 | 目標 |
| --- | --- |
| 月次提出漏れ | 締切時点で 0 件（未提出者を可視化して解消する） |
| 日次登録の容易さ | スマートフォンで通常30秒以内に入力できる |
| 管理者の確認 | 月次の提出状況・未入力件数を一覧で確認できる |
| 運用規模 | 社員50名、管理者1〜5名を想定する |
| 運用費 | アプリのホスティング、DB、通知に月額0円を目標とする |

> **費用に関する前提**: 「完全無料」は採用サービスの無料枠内で利用することを意味する。無料枠・アカウント要件・利用規約は変更され得るため、導入前および四半期ごとに管理者が確認する。独自ドメイン、SMS、商用メール配信、AI API の実行費は本要件の無料範囲に含めない。

## 2. 採用構成と選定理由

リポジトリの指定構成（`frontend/`、`backend/`、`docs/`、`.github/workflows/`）を採用する。フロントエンドとバックエンドを分離することで、スマートフォンUIの改善とサーバーAPIの保守を独立して行えるためである。

| パーツ | 採用案 | 選定理由 | 無料運用上の留意点 |
| --- | --- | --- | --- |
| フロントエンド | HTML / CSS / JavaScript（フレームワークなし） | 指定構成に沿い、画面数が少ないため依存関係を増やさずに軽量・保守しやすい。 | Cloudflare Pages Free 等の静的ホスティングを利用する。 |
| APIサーバー | Java 21 + Spring Boot 3 | 指定された `backend/` のSpring Boot構成に沿う。認証、バリデーション、定時処理、Excel出力をJavaで一元管理できる。 | Oracle Cloud Always Free VM 等の常時無料枠へDockerで配置する。空き不足・無料枠変更時の移設手順を用意する。 |
| データベース | PostgreSQL（APIサーバーと同一VMのDocker） | 勤怠・承認状態・監査ログの整合性をトランザクションで守り、将来の集計にも対応しやすい。 | DB専用マネージドサービスは使わず、暗号化バックアップを同一無料枠のObject Storage等へ保管する。 |
| 認証 | 社員ID + 初期パスワード、Spring Security、BCrypt | 外部ID基盤やメール送信サービスを必須にせず、無料で完結する。パスワードは平文保存しない。 | 初期パスワード配付と再設定は管理者本人確認のうえ実施する。 |
| 通知 | アプリ内の未提出警告 + Web Push（許可者） | 月末の提出忘れ対策の中心。SMS・有料メールを使わず、ブラウザ通知で能動的に促せる。 | 通知拒否やiOSの制約があるため、管理者画面の未提出一覧を最終フォロー手段とする。 |
| Excel出力 | Apache POI（`.xlsx`） | 管理者がそのまま確認・加工できるExcelをサーバー側で安定生成できる。 | ライブラリはOSSを利用する。 |
| バッチ | Spring `@Scheduled` | 月末・締切前の対象判定をサーバー側で行い、利用者のアクセス有無に依存しない。 | VM停止を検知する監視を設定する。 |
| CI | GitHub Actions | push時にテストと静的チェックを自動化し、手作業による品質低下を防ぐ。 | privateリポジトリの無料枠・利用時間は組織設定を確認する。 |

### 2.1 無料枠の実現性

50名が平日に各2回打刻しても、おおむね100 API呼び出し/日（画面表示等を含めても十分小規模）である。Cloudflare Workers Free は1日10万リクエスト、D1 Free は1日500万行読取・10万行書込の上限が公表されており、将来Spring Bootをサーバーレス構成に置換する場合にも規模上は余裕がある。Cloudflare Pages の静的アセット配信も無料である。

本版は指定構成を優先してSpring Bootを採用する。Oracle Cloud はAlways Freeのコンピュートを提供しているが、アカウント作成時の本人確認・リージョンの空き状況を事前確認すること。これが確保できない場合の代替案は、`backend/` のREST仕様を維持したままCloudflare Workers + D1へ移植することである。無料枠を超えた場合は自動課金を有効にせず、リクエストを停止して管理者へ通知する。

参考（いずれも導入時に再確認すること）：[Cloudflare Workersの料金・上限](https://developers.cloudflare.com/workers/platform/pricing/)、[Cloudflare Pagesの料金](https://developers.cloudflare.com/pages/functions/pricing/)、[Oracle Cloud Free Tier](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier.htm)

## 3. 利用者と権限

| 役割 | できること | できないこと |
| --- | --- | --- |
| 社員 | 自分の打刻登録・修正、月次一覧確認、月次提出、通知設定 | 他社員の勤務情報・提出状況の閲覧、Excel出力 |
| 管理者 | 全社員の月次提出状況閲覧、並べ替え・絞込み、提出状態の差戻し、Excel出力、社員アカウント管理、締切設定 | パスワード平文の閲覧 |

初期版では、労働時間の承認・給与計算・休暇残数管理は対象外とする。必要になった場合は別機能として要件追加する。

## 4. 機能要件

### 4.1 社員向け

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| FR-01 | ログイン | 社員IDとパスワードでログイン・ログアウトできる。未認証で勤怠APIへアクセスできない。 |
| FR-02 | 日次打刻 | 対象日、出勤時刻、退勤時刻、休憩分、備考をスマートフォンから登録・修正できる。 |
| FR-03 | 入力検証 | 退勤が出勤以前、休憩が勤務時間以上、未来日、提出済み月の本人変更をエラーにする。日跨ぎ勤務は初期版では対象外とし、備考と管理者対応へ誘導する。 |
| FR-04 | 月次一覧 | 当月・過去月の各日の入力有無、勤務時間、未入力日、月合計を表示する。 |
| FR-05 | 月次提出 | 社員が当月の内容を確認し、「提出する」を明示操作したときのみ `提出済み` とする。提出時刻を記録する。 |
| FR-06 | 提出前チェック | 未入力の平日、矛盾する時刻、必須項目不足がある場合、提出できず該当日を表示する。休日・会社休日は管理者設定により除外する。 |
| FR-07 | リマインド | 月末7日前、3日前、前日、締切当日に、未提出者へアプリ内表示と許可済み端末へのWeb Pushを行う。通知頻度は同日最大1回とする。 |
| FR-08 | 提出後の扱い | 提出後は社員が編集できない。訂正が必要な場合は管理者に差戻しを依頼し、差戻し後に再提出できる。 |

### 4.2 管理者向け

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| FR-09 | 提出状況一覧 | 対象月の社員名、部署、入力完了率、提出状態、提出日時、未入力日数を一覧表示する。 |
| FR-10 | 検索・並べ替え | 氏名・部署・提出状態で絞込みでき、氏名・提出状態・提出日時・未入力日数で昇順/降順ソートできる。 |
| FR-11 | 差戻し | 管理者は理由を入力して提出済みデータを差戻しできる。対象社員へアプリ内通知し、履歴を残す。 |
| FR-12 | Excel出力 | 対象月、対象部署、提出状態を指定して `.xlsx` をダウンロードできる。出力には社員、日付、出勤、退勤、休憩、勤務時間、備考、提出状態、提出日時を含める。 |
| FR-13 | 社員管理 | 管理者は社員の作成、無効化、部署設定、管理者権限の付与・剥奪を行える。無効化しても勤怠履歴は削除しない。 |
| FR-14 | 締切設定 | 月ごとの提出締切日と会社休日を設定できる。既定は翌月3日 23:59（日本時間）とする。 |

### 4.3 提出状態の定義

| 状態 | 意味 | 遷移 |
| --- | --- | --- |
| 未入力 | 対象月に勤怠登録がない、または提出前チェック未完了 | 入力中 / 提出済み |
| 入力中 | 一部または全日を登録済みだが未提出 | 提出済み |
| 提出済み | 社員が内容を確認して提出した | 差戻し |
| 差戻し | 管理者が修正を要求した | 入力中 / 提出済み |

## 5. 非機能要件

| 分類 | 要件 |
| --- | --- |
| 対応端末 | iOS / Android の主要ブラウザ、およびPCの最新版Chrome・Edge・Safariで利用できる。画面幅360px以上で操作できる。 |
| 可用性 | 原則24時間利用可能。無料基盤の計画外停止は管理者が復旧対応する。RTOは24時間、RPOは前日バックアップ時点とする。 |
| 性能 | 通常操作（画面表示・打刻保存）は95パーセンタイルで3秒以内を目標とする。Excel出力は50名×31日で30秒以内を目標とする。 |
| 時刻 | 日本標準時（Asia/Tokyo）を業務時刻として統一し、DBにはUTCとタイムゾーンを保持する。 |
| セキュリティ | HTTPS必須、パスワードはBCryptハッシュ、セッションCookieは`HttpOnly`・`Secure`・`SameSite`、APIは役割認可、入力値検証、レート制限、監査ログを実装する。 |
| 個人情報 | 氏名・社員ID・勤怠情報を必要最小限で保持する。バックアップは暗号化し、管理者以外へ公開しない。 |
| 監査性 | 打刻の作成・更新、提出、差戻し、Excel出力、権限変更について、誰がいつ何を行ったか記録する。 |
| バックアップ | PostgreSQLの論理バックアップを毎日実行し、復元手順を文書化して四半期ごとに復元テストする。 |

## 6. データ要件（概念）

| エンティティ | 主な項目 | 保持目的 |
| --- | --- | --- |
| employees | 社員ID、氏名、部署、ロール、有効状態 | 利用者・権限制御 |
| attendance_records | 社員、対象日、出勤、退勤、休憩、備考、更新日時 | 日次勤怠 |
| monthly_submissions | 社員、対象月、状態、提出日時、差戻し理由 | 月次提出管理 |
| holidays | 日付、名称、種別 | 提出前チェックの対象日判定 |
| notification_subscriptions | 社員、端末のPush購読情報、有効状態 | Web Push通知 |
| audit_logs | 操作者、操作種別、対象、日時、差分 | 監査・調査 |

詳細な物理設計は `docs/04_ER図.md` および `docs/06_テーブル定義.md` で決定する。

## 7. AIを活用した設計・開発手順

AIは設計・実装・テストを補助するために使い、本番の勤怠判定や個人情報処理を外部AIに委ねない。生成物は必ず人間がレビューし、実在の社員情報・本番の認証情報をプロンプトへ入力しない。

1. **要件を固定する**: 本書をGitでレビューし、提出締切、休日、日跨ぎ勤務、差戻しの運用責任者を決める。曖昧なまま実装を始めない。
2. **基本設計を作る**: AIに本書をコンテキストとして渡し、画面遷移、権限マトリクス、システム構成、状態遷移を `docs/02_基本設計.md` として下書きさせる。人間が無料枠・セキュリティ・運用の前提を承認する。
3. **画面・データ・APIを設計する**: AIを使って `03_画面設計.md`、`04_ER図.md`、`05_API設計.md`、`06_テーブル定義.md` のたたき台を作る。日時形式、エラー形式、権限、提出状態は文書間で一貫させる。
4. **受入条件からテストを先に作る**: 本書のFR番号ごとに正常系・異常系・権限境界を `08_テスト仕様書.md` へ落とす。特に未提出通知、提出後編集禁止、Excel内容をテストする。
5. **最小実装を生成・レビューする**: AIに小さな単位で、DBマイグレーション、認証、打刻API、月次提出、管理画面、Excel出力の順でコード案を作らせる。各変更は人間が差分レビューしてからマージする。
6. **自動テストと静的解析を通す**: GitHub Actionsでバックエンド単体・結合テスト、フロントエンドの静的チェック、依存関係脆弱性確認を実行する。AIが書いたテストだけに頼らず、境界ケースを追加する。
7. **ステージングで実利用検証する**: 架空社員データ50名・1か月分で入力、通知、提出、差戻し、Excel出力、復元を実施する。実社員へ公開する前に管理者が結果を承認する。
8. **無料基盤へ本番配置する**: SecretsをGitへ置かず、ホスティング側の秘密情報として登録する。HTTPS、CORS許可元、DBバックアップ、監視、障害連絡先を設定する。
9. **初月を伴走する**: 締切7日前から管理者が未提出一覧を確認し、通知不達者をフォローする。初月終了後、提出漏れ数・通知許可率・問い合わせを振り返り、改善をIssue化する。

## 9. 未決事項

実装開始前に以下を決定・承認する。

1. 日跨ぎ勤務、複数回の出退勤、休暇・休日出勤を初期版の対象に含めるか。
2. 社員ID・初期パスワードを誰がどの手段で配付するか。
3. Web Pushを許可しない社員への締切連絡の社内運用。
4. Oracle Cloud Always Freeのアカウント・リージョンを利用できるか、および代替のCloudflare構成を承認するか。
5. 勤怠データの保存期間、管理者の責任者、削除・退職者処理の規程。
