## 1. プロダクトの目的

Clokkaは、社員約50名がスマートフォンまたはPCのブラウザから日々の勤怠を登録し、月次勤務実績の**提出忘れをなくす**Webアプリである。管理者はブラウザで提出状況を一括確認し、月次データをExcel形式で出力する。

### 成功指標

| 指標 | 目標 | 測定方法 |
| --- | --- | --- |
| 月次提出漏れ | 締切時点で0件 | 月次の提出状態一覧 |
| 日次入力の操作性 | 通常の入力を30秒以内 | 代表利用者による受入テスト |
| 管理者確認 | 未提出者を対象月・部署・状態で特定可能 | 管理画面の受入テスト |
| 運用コスト | アプリ稼働に必須のサービスを無料枠内で運用 | Phase 2/5/11の無料枠確認記録 |

## 2. スコープ

### 初期リリースに含める（Must）

1. 社員・管理者の認証と役割によるアクセス制御。
2. 社員本人による日次の出勤時刻、退勤時刻、休憩時間、備考の登録・修正。
3. 月次一覧、未入力日の表示、月次提出、提出後の編集禁止、管理者による差戻し。
4. 月末提出漏れ防止のための未提出表示、通知を許可した端末へのWeb Push、管理者一覧。
5. 管理者による検索・絞込み・並べ替え、月次Excel（`.xlsx`）出力。
6. 会社休日・休日の設定と、提出前チェックでの対象日判定。
7. 操作履歴、日次バックアップ、HTTPS、権限確認を含む最低限の運用・セキュリティ対策。

### 初期リリースから除く（Out of Scope）

- 給与計算、残業代計算、法定帳票の自動作成
- シフト作成、工数管理、経費精算
- SMS通知、有料メール配信、ネイティブモバイルアプリ
- 生体認証、位置情報、QRコード打刻
- 複数会社・テナントの運用

### 将来検討・運用上の未決事項

- 休暇（有給・欠勤・代休等）の申請・表示は初期リリースでは実装せず、将来機能として検討する。
- Web Pushを許可しない社員に対する締切連絡の担当者・連絡時期・利用する社内連絡手段は未決とする。

## 3. 用語と業務ルール

| 用語 | 定義 |
| --- | --- |
| 勤務日 | 勤務を開始した日本時間（Asia/Tokyo）の日付。日跨ぎ勤務も出勤時刻の日付に属する。 |
| 日跨ぎ勤務 | 出勤から退勤までが日付をまたぐ勤務。例: 8月1日23:00出勤、8月2日02:00退勤は、8月1日の勤務実績とする。 |
| 勤務実績 | 1社員・1勤務日について登録する出勤、退勤、休憩、備考の記録。 |
| 月次提出 | 社員が対象月の勤務実績を確認し、内容を確定する明示操作。 |
| 差戻し | 管理者が理由を示して月次提出を編集可能な状態へ戻す操作。 |
| 締切 | 月次提出を完了すべき日時。既定値は翌月3日23:59（JST）とし、管理者が変更できる。 |
| 会社休日 | 管理者が設定し、提出前の未入力チェック対象から除外する日。 |

### 日跨ぎ勤務の確定ルール

1. 勤務日は必ず出勤時刻の暦日とする（プロダクトオーナー承認済み）。
2. 退勤時刻が出勤時刻より早い場合、翌日の退勤として扱う。
3. 勤務時間は、出勤から退勤までの経過時間から休憩時間を引いて計算する。
4. 24時間以上の連続勤務、複数回出退勤は初期リリースでは許可しない。入力エラーとし、管理者に相談する。
5. 月末に開始して翌月に終了した勤務は、勤務開始月の提出対象とする。

## 4. 役割と権限

| 操作 | 社員 | 管理者 |
| --- | :---: | :---: |
| 自分の勤怠の作成・提出前修正 | 可 | 可 |
| 自分の月次提出 | 可 | 可 |
| 他社員の勤怠閲覧 | 不可 | 可 |
| 提出状況の一覧・検索・ソート | 不可 | 可 |
| 月次の差戻し | 不可 | 可 |
| Excel出力 | 不可 | 可 |
| 社員・権限・休日・締切の管理 | 不可 | 可 |

### アカウントライフサイクルと管理者Bootstrap

* **初期管理者:** DB構築直後は `ADMIN` が0人である。アプリケーションは起動時に `BOOTSTRAP_ADMIN_*` 環境変数（`BOOTSTRAP_ADMIN_CODE` / `BOOTSTRAP_ADMIN_PASSWORD` / `BOOTSTRAP_ADMIN_NAME` / `BOOTSTRAP_ADMIN_DEPARTMENT_ID`）を読み、有効な `ADMIN` が0人の場合のみ1件を冪等に作成する。既に `ADMIN` が1件以上存在する場合は何もしない。Bootstrapで作成された管理者は初回ログイン後にパスワード変更が可能であり、推奨される。
* **複数管理者:** `ADMIN` は複数人存在可能である。2人目以降は既存の `ADMIN` が `POST /admin/employees`（招待）または `PATCH /admin/employees/{id}`（既存 `EMPLOYEE` の昇格）で作成する。`employees.role` は `EMPLOYEE` / `ADMIN` のみであり、人数制限は設けない。
* **最後の管理者保護:** 有効な `ADMIN` が1人の状態で、その者への `role=EMPLOYEE` への降格または `is_active=false` への無効化は禁止する。APIは `409 LAST_ADMIN_RESTRICTION` で拒否し、UIでもボタンを無効化する。
* **社員招待:** 管理者は社員を `POST /admin/employees` で招待する際、パスワードは含めない。社員は `is_active=false` で作成され、招待トークン（有効期限24時間、1回限り）が発行される。社員本人が招待URLから `POST /auth/activate` でパスワードを設定して `is_active=true` となる。トークンは推測困難な128bit以上のランダム値とし、平文はDBに保存しない。
* **認証:** 社員・管理者ともに共通の `POST /auth/login`（社員ID+パスワード → セッションCookie）で認証し、`role` により認可する。管理者専用の別認証機構や公開 `/setup` 画面/APIは設けない。
* **無効化:** 退職者は `is_active=false` とする。無効化されたアカウントはログイン不可であり、履歴は保持される。

### Push通知状態の定義と具体例

| 表示状態 | 意味 | 具体例 | 管理者の解釈 |
| --- | --- | --- |
| 許可 (`GRANTED`) | 少なくとも1台の端末で通知が許可され、有効なPush購読情報がサーバーへ登録されている。 | 社員がiPhoneの通知設定で「許可」を選び、ClokkaがPush購読を正常登録した。 | ClokkaからPushを送信できる社員。 |
| 拒否 (`DENIED`) | 有効な購読端末がなく、報告済みの対応端末すべてで通知が明示的に拒否されている。 | Chromeの通知確認で「ブロック」を選んだ。 | Pushでは連絡できない。拒否者フィルタの対象。 |
| 未設定 (`DEFAULT`) | 対応端末だが、通知許可をまだ選んでいない、または許可後に購読登録が未完了・失効している。 | 通知の確認ダイアログをまだ開いていない／「許可」後に通信失敗し購読を登録できなかった。 | 通知設定画面を案内すればPush可能になる余地がある。 |
| 非対応 (`UNSUPPORTED`) | 利用端末・ブラウザがWeb Pushまたは通知APIを提供しない。 | 古いブラウザ、会社ポリシーでPush APIを無効化したブラウザを利用している。 | その端末からはPushを使えない。 |
| 未確認 (`UNKNOWN`) | 通知状態をClokkaへ一度も報告していない。 | 初回ログイン後に通知設定画面を開いていない／端末情報を消去した。 | 利用可否を判定できないため、社員へ設定画面の確認を依頼する。 |

複数端末を利用する社員は、1台でも有効な購読があれば`許可`とする。購読が存在しない場合は、`未設定`の端末が1台でもあれば`未設定`、すべての対応端末が`拒否`なら`拒否`、すべて非対応なら`非対応`、報告がなければ`未確認`とする。

## 6. 非機能要件

| ID | 要件 | 受入条件 |

| NFR-01 | 利用性 | 360px幅以上のiOS/Android主要ブラウザと、最新版Chrome・Edge・Safariで主要操作ができる。 |
| NFR-02 | 性能 | 通常の画面表示・保存は95パーセンタイルで3秒以内、50名×31日のExcel出力は30秒以内を目標とする。 |

| NFR-05 | バックアップ | DBバックアップを毎日実行し、四半期に一度復元テストを行う。 |
| NFR-06 | 保守性 | 画面、API、DBマイグレーション、テストを分離し、要件IDからテストまで追跡可能にする。 |

## 10. Phase 1 の完了判定

本書の内容と文書移行方針がプロダクトオーナーに承認された時点でPhase 1は完了とする。Push通知拒否者の外部連絡は初期リリースの対象外とし、運用開始前の確認事項として保持する。Phase 2のアーキテクチャ・技術選定へ進む。
